# Report Management Frontend And Backend Boundary

The report management UI will live inside RuoYi-Cloud's `ruoyi-ui` so it can be exposed as a normal RuoYi menu entry, while the report file, version, preview, upload, and AI audit capabilities will be provided by a Python backend. This keeps the user-facing workflow in the existing operations console and lets the document parsing, file storage, asynchronous audit execution, and DeepSeek integration evolve outside the Java microservice stack. The Python backend must own these capabilities because the existing standalone Python DOCX file service is planned for removal and cannot be a runtime dependency. The old file service's same-name replacement behavior is intentionally not reused; report uploads must be versioned and retain prior files.
